VMWare、Hyper-V、iperf 和嵌套虚拟化

发表于2026-01-14|更新于2026-01-14
|总字数:20k|阅读时长:1:11分钟

VMWare Workstation 中创建的虚拟机默认采用 e1000 或 pcnet32 网卡：

它们的性能表现并不理想。尤其是在开启了 Hyper-V 的情况下，iperf 测速能达到 100Mbps 就不错了：

如果需要更高的性能，可以使用 vmxnet3 类型的网卡。它可以将速度提升至大约 3Gbps：

尽管如此，这个速度仍然算不上令人满意。要知道这可是正经的 企业级网卡，在 vSphere 中，它的链路速度甚至可以达到 65Gbps。

那么为什么在 Workstation 中性能会大打折扣呢？一个可能的原因是在开启 Hyper-V 之后，VMWare 实际上转变为 Type 2 类型的 hypervisor，对硬件的访问必须经过 WHP (Windows Hypervisor Platform)，从而大幅降低了 I/O 效率。具体的工作模式可以在 vmware.log 日志文件中查看：

直接关闭 Hyper-V 并不是一个理想的解决方案，因为 WSL 以及 Windows 的某些内核功能（比如内存完整性等）都依赖于 Hyper-V。
更好的做法是直接使用 Hyper-V 作为 hypervisor 平台。在这种模式下，iperf 网络测试能够轻松跑出单线程 5Gbps、多线程 10Gbps 的速度：

虚拟化厂商常宣传“性能损耗不到 5%”，但这通常是指用户态计算密集型的理想情况。一旦面对用户态/内核态切换、高中断频率或者 IO 密集的任务，性能往往会出现显著下降。虽然 VT-x/AMD-V 等技术进一步降低了虚拟化开销，但在嵌套虚拟化环境下，性能表现仍难以令人满意。

在 Windows 上，如果已经启用了 Hyper-V，最好将所有的虚拟机全部迁移到 Hyper-V 运行。这样可以充分利用 Hyper-V 的 Type 1 hypervisor 的性能优势，提高虚拟化效率。
